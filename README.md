# 📊 怪物彈珠抽卡分析器（Monster Strike Gacha Analyzer）

這是一個為《怪物彈珠》玩家設計的進階抽卡預測工具。不同於傳統的「單抽實況模擬器」，本工具採用 **蒙地卡羅方法 (Monte Carlo method)**，在瀏覽器端瞬間執行 **1,000,000 次**（預設）大數據平行模擬，試圖近似計算包含「非洲玉」保底機制在內的抽卡機率分佈。

幫助玩家在抽卡前進行較為科學的寶珠資源規劃，減少完全「瞎抽」的情況。

## ✨ 核心功能 (Features)

本工具是一個**單頁資料儀表板**：左側設定參數、右側立即看結果，載入頁面時會自動跑一次模擬，不用先按任何按鈕。

### 1. 模式一：目標達成所需抽數（累積分佈函數 CDF）

- **情境**：「我想抽到艦隊，大概需要準備多少寶珠？」
- **功能**：輸入目標隻數，系統會透過大量模擬計算出：
  - 25% 抽到目標的抽數（幸運落點）
  - 50% 抽到目標的抽數（中位數）
  - 85% 抽到目標的抽數（安全準備線）
  - 99% 抽到目標的抽數（極端非酋線）
- **視覺化**：
  - 「達成率 vs 抽數」曲線圖（CDF），圖上標出 25 / 50 / 85 / 99 四條百分位基準線
  - X 軸可一鍵切換 **抽數 / 寶珠數**
  - **曲線疊圖**：可把目前的曲線存檔（最多 3 條），用來比較不同機率或不同目標隻數的落差
  - **分位數抽數誤差圖**：每個百分位點的 95% 信賴半寬，讓你看得出「99% 其實不是精確值」
  - 里程碑表：各達成率所需抽數、寶珠數與 95% 區間

### 2. 模式二：預期獲得數量（機率密度函數 PDF）

- **情境**：「我手上現在有 250 顆寶珠（50 抽），預期可以抽到幾隻目標角色？」
- **功能**：輸入預計抽數，系統會估算在該抽數下：
  - 抽到 0、1、2、3… 隻目標角色的機率（含機率密度長條圖）
  - 整體的數學期望值（平均可得幾隻）與 95% 信賴區間
  - **期望值 vs 抽數**曲線（同一條模擬中累積到各抽數時的期望隻數，含 95% 信賴帶）
  - 這段期間平均會觸發幾次非洲玉

## 💡 常見機率迷思 (FAQ & Tips)

### 1. **雙 UP 卡池機率可以直接相加嗎？**

**Q: 卡池裡有兩隻目標角色 A、B，各自 1.2%。如果我想「抽到 2 隻」，是不是可以把機率 1.2% + 1.2% = 2.4%，然後目標數量設 2？**

**A: 要看你的「目標定義」是什麼：**

1. **情境一：你只想要「任意兩隻」這類角色**
   例如：A / B 你都 OK，結果可能是 2 隻 A、2 隻 B、1 隻 A + 1 隻 B。
   在這種情況下，A 與 B 對你來說是「等價」的中獎事件，**可以近似視為總機率 2.4%，目標數量 = 2** 來做估算。

2. **情境二：你一定要「A 一隻 + B 一隻」都抽齊**
   抽到第 1 隻 A 之後，A 對你來說就變成「溢出」，真正有用的只剩 B 那 1.2%。
   等於你前期機率是 2.4%，但中途會忽然掉回 1.2%。
   這在統計上屬於「集齊問題 (Coupon Collector's Problem)」，**不能單純用 2.4% 和『兩隻』來替代**，實際需要的抽數會比「任意兩隻」多很多。

👉 **目前這個工具的「目標數量」設定，是針對「同一隻角色的累計 copies」而設計的。**
如果要精準分析「湊齊多隻不同角色」，需要另外寫專門的多目標模擬邏輯。

### 2. **非洲玉觸發後機率真的會放大嗎？**

**Q: 非洲玉是 100% 五星，為什麼目標角色機率會從 1.2% 變成 10%？**

**A: 是的，邏輯是這樣的：**

常規一抽中五星只有 12%，也就是「每 12 抽才有 1 隻五星」，而那隻五星的機率分母是 12%。
非洲玉是 **100% 必定出五星**，所以同一個目標角色在非洲玉中的機率被放大為：

```
目標非洲玉機率 = 目標常規機率 ÷ 五星基礎出率
              = 1.2% ÷ 12%
              = 10%
```

也就是一抽非洲玉的期望收益，等於常規抽 8.3 抽的目標產出量。

**注意**：這假設官方沒有在非洲玉中「額外調整」機率分佈。

### 3. **模擬器顯示 85% 機率需要 100 抽，為什麼我實際抽了 80 抽就出貨了？**

**Q: 模擬結果與實際經驗有差異，是模擬器錯了嗎？**

**A: 完全正常！**

模擬器計算的是「大數法則下的分佈」，不是「您一定會抽到」。
85% 達成率的意思是：有 85% 的人在 100 抽之內出貨，剩下 15% 的人要更久。你抽 80 抽就出貨，代表你落在那 85% 裡面 —— 恭喜，你比大多數人幸運。

### 4. **每次重新計算結果都略有不同，為什麼？**

**Q: 相同參數點擊兩次，結果略有差異，是 Bug 嗎？**

**A: 這是蒙地卡羅方法的特性！**

每次計算都會重新抽取大量隨機樣本，樣本數有限時，抽到罕見事件的機率就會有小幅波動。
想要完全相同的結果？在「亂數種子」填入同一組數字即可重現；樣本數拉越高，數值收斂得越快。

### 5. **為什麼曲線圖會有明顯的「階梯」？**

**Q: 圖表上有好幾個陡升點，什麼意思？**

**A: 這就是非洲玉保底機制的數學特徵！**

曲線在平緩處慢慢上升（四星的碎片慢慢累積），到了碎片滿 50 的位置，非洲玉強制發動，該抽數之後出現目標的機率會瞬間拉高，於是曲線出現一段陡升。
階梯的間距大約是 50 ÷ 四星率 ≈ **57 抽**（12% 池），這也是「平均 57 抽一次非洲玉」的由來。

---

### 6. **非洲玉是抽哪一池的角色？跨池有效嗎？**

**A: 官方公告寫得很清楚：非洲玉（星之玉轉蛋）出現的角色，與「蒐集到第 50 顆碎片當下所抽的那個池子」相同。**

所以它可以跨池使用：刻意在 48/50 或 49/50 停手，等到心儀的卡池（通常是超獸／激獸神祭）開啟時再把非洲玉用掉。
本工具的模擬無法預測「碎片滿 50 的當下你在哪一池」，因此非洲玉一律以你設定的目標機率計算，屬於簡化模型。

---

### 7. **非洲玉可以「自選」嗎？**

**A: 可以，而且有隱藏機制。** 依玩家社群的統計：同一個池子連續觸發 3 顆非洲玉後，第 4 顆起有機會出現「自選」（可指定想抽的角色）。

- 第 4 顆：自選機率約 **16.7～17%**
- 第 6 顆或之後：約 **25%**
- 出自選後計數會 reset，需重新累積

若要靠自選拼特定角色，社群建議至少準備 1,000 珠以上（以 285 珠一顆非洲玉換算，約能累積 3～4 顆）。
自選機率屬於官方未公開的隱藏機制，本工具的模擬未納入。

---

### 8. **目前遊戲的五星出率到底是 12% 還是 8.4%？**

**A: 兩者都存在，但現行版本以 12% 為主。**

- **12%**：超獸神祭、激獸神祭、英雄祭等「祭」池；官方自 2020/04/03 起，也把原本 8.4% 的寶珠轉蛋統一提升為 12%。
- **8.4%**：2020 年 4 月之前的舊制，以及部分特殊轉蛋（星塵／特玉等）仍可能見到接近 8.4% 的配置。

另外提醒：限定的機率會隨「限定角色是否加倍」而變動（加倍 0.6%、未加倍 0.4%），常設與期間限定角色則常見 0.9% / 1.2% / 1.4% / 1.8%，本工具的預設按鈕已把這些常見值一併收錄。

## 🛠 技術細節 (Technical Details)

- **核心演算法**
  - 使用 JavaScript 在瀏覽器端實作 Monte Carlo Simulation。
  - 每次運算預設執行：
    - 模式一：約 1,000,000（預設）次模擬「抽到目標 N 隻所需抽數」
    - 模式二：約 1,000,000（預設）次模擬「在固定抽數下抽到的目標隻數」
  - 隨機數使用 `mulberry32` 偽亂數產生器，指定種子即可重現結果。

- **機率模型（可依實際卡池調整）**
  - 常規五星出率：12%（超獸／激獸／英雄祭；官方自 2020/04/03 起已把原 8.4% 的寶珠轉蛋統一提升為 12%，★4 由 91.6% 降為 88%）
  - 四星出率：100% − 五星出率（每次四星，星星碎片 +1）
  - 星星碎片滿 50 觸發「非洲玉」，保證五星，超出 50 的碎片保留
  - 非洲玉中的目標角色命中率：
    \[ \text{目標非洲玉機率} = \frac{\text{目標常規機率}}{\text{五星基礎出率}} \]
    例如：目標常規 1.2%、基礎出率 12%，則非洲玉中為 10%（0.4% → 3.33%、0.6% → 5%、0.9% → 7.5%、1.8% → 15%，與玩家社群實測一致）。
  - 已知簡化：非洲玉的角色來自「碎片滿 50 當下所抽的池子」，本工具無法預測你在哪一池，故一律以設定的目標機率計算。

- **檔案結構**

```
.
├── index.html          頁面結構與內容（儀表板）
├── ui.css              視覺系統（儀表板版面、網狀漸層背景、圖表主題）
├── logic.js            介面、圖表、動畫與 Worker 調度
├── sim-core.js         蒙地卡羅核心（Worker 與主執行緒共用）
├── sim-worker.js       Web Worker 封裝（進度回報、可取消）
└── assets/
    ├── ms-logo.svg     官方網站素材（Logo）
    ├── mascot-*.png    官方網站素材（吉祥物）
    ├── element-fire.png / monster-head.png
    └── vendor/chart.umd.js
```
